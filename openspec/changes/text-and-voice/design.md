# Design

## Context

См. proposal.md — Why. Требования — в `specs/pipeline`, `library`, `assets`, `timeline`.

Сейчас `library.db` — `user_version` 3, таблицы `folders`, `shorts`, `bins`, `assets`. У ролика есть `status` (`draft`), нет темы и сценария. Таблицы задач нет. Сети в `find_package` нет: `Qt6Network.dll` копируется только как зависимость Multimedia. `place_asset(..., "a1", ...)` уже кладёт звук. Живых вызовов моделей нет.

## Goals / Non-Goals

**Goals:**

- Один контракт инструмента: вход, выход, отмена, прогресс, ошибка. Конвейер этапа 7 — текст, затем голос.
- Ключи вне библиотеки, тесты без живой сети.
- Голос проходит тот же ingest и `place_asset`, что ручной звук.

**Non-Goals:**

- Второй HTTP-клиент под ElevenLabs.
- Очередь нескольких роликов сразу.
- Нарезка TTS на сцены и раскладка клипов по сценам.

## Decisions

### Инструмент и оркестратор, не вызов из QML

`CModelTool` — один шаг: `run`, отмена, прогресс. `CChatTool` шлёт OpenAI-совместимый `POST {base}/v1/chat/completions`. `CSpeechTool` шлёт `POST {base}/v1/audio/speech` на тот же `base`. `CPipeline` запускает их по порядку, пишет задачу и статус ролика, после голоса вызывает `import_media` и `place_asset` на `a1`. Шага видео в оркестраторе нет.

Рассматривался вызов `QNetworkAccessManager` прямо из QML. Отмена, повтор и запись сценария тогда разъехались бы с тестами.

Рассматривался ElevenLabs как первый TTS. ТЗ держит общий HTTP-контракт; второй адаптер — отдельное изменение.

Умолчания настроек: `https://api.openai.com`, чат `gpt-4o-mini`, речь `tts-1`, голос `alloy`. Пользователь меняет адрес, модели, голос и ключ. Один ключ на оба шага.

### Транспорт подставляется в тесте

`CHttpTransport` — `post` с URL, заголовками и телом. Боевой транспорт — `QNetworkAccessManager`. Тест ставит заглушку: фиксирует URL и JSON, отдаёт готовый ответ или ошибку, не ходит в сеть. `shell_tests` с `QT_QPA_PLATFORM=offscreen` живой API не вызывают.

Отмена — флаг на оркестраторе и `abort` текущего ответа. Между шагами флаг проверяется до второго `post`.

### Ключи — DPAPI-файл в AppData, не sqlite

`CSecretStore` шифрует JSON `{base_url, chat_model, tts_model, voice, api_key}` через `CryptProtectData` и пишет файл в `QStandardPaths::AppLocalDataLocation`. Ключ один на пользователя, не на папку библиотеки.

Рассматривалась строка в `library.db`. ТЗ запрещает открытый текст в sqlite; DPAPI вокруг колонки всё равно оставляет секрет в каталоге, который копируют целиком.

Рассматривался Credential Manager. Один блоб настроек проще тестировать одним файлом.

В тесте — память вместо DPAPI: проверка, что `library.db` и `project.json` ключа не содержат. Поле ключа в диалоге после перезапуска не показывает сохранённую строку, только признак «ключ задан».

### Тема и сценарий в sqlite, задача рядом

Миграция `3 → 4`: `shorts.topic`, `shorts.script`, таблица `tasks` (`id`, `short_id`, `step` `text|voice`, `status` `running|done|error|cancelled|interrupted`, `progress`, `error`). `PRAGMA user_version = 4`.

Рассматривался `shorts/<id>/script.json`. Тема тогда жила бы отдельно от карточки; поиск и статус уже читают sqlite.

Сценарий — текст ответа чата. Шаблон просит JSON со сценами, но конвейер не разбирает сцены: TTS получает весь текст, один клип на `a1`. Разбор сцен — этап 8.

Статус ролика: `generating`, пока есть `running` задача этого id; иначе `draft`. `ready` / `published` этот этап не пишет.

При `open` все `running` становятся `interrupted`. Повтор создаёт новую задачу на тот же ролик: если сценарий уже есть, шаг текста пропускается и сразу идёт голос.

### UI: диалоги, не новая панель

Меню ролика: «Тема и голос» — диалог по центру окна, как промпт: поле темы, залитая «Сгенерировать», отмена. На карточке во время задачи — шаг и прогресс, кнопки отмены и повтора. Настройки ключа — отдельный диалог из шапки (кнопка рядом с каналами, не заглушка каналов).

Рассматривалась третья колонка у кадра. ТЗ не добавляет панель на этапе 7; доки уже заняты медиа, папками и таймлайном.

### Сборка

В `find_package` и `target_link_libraries` добавляется `Qt6::Network`. Копирование `Qt6Network.dll` уже есть в `youtube_copy_multimedia`. Новые файлы: `secret_store`, `http_transport`, `chat_tool`, `speech_tool`, `pipeline` рядом с `library_store`.

## Risks / Trade-offs

- [Длинный сценарий не влезает в один TTS-запрос] → ошибка шага, сценарий остаётся, пользователь коротче тему или правит сценарий руками в следующем изменении. Нарезка по сценам не входит.
- [Совместимый сервер без `/v1/audio/speech`] → ошибка голоса, текст не затирается. ElevenLabs отдельно.
- [Повтор с уже лежащим голосовым клипом] → новый ingest + новый клип на `a1` поверх (overwrite в позиции 0), старый ассет остаётся в пуле, если на него есть ссылка.
- [Старые тесты ждут только `draft`] → явный статус `generating` только на время `run` в новых случаях; миграция v3 сохраняет прежние черновики.

## Migration Plan

При `open` версии 3: `ALTER TABLE shorts` двух колонок, `CREATE TABLE tasks`, `user_version = 4`. Ролики, бины и ассеты не трогать. Откат схемы не делается: как у перехода 2 → 3, старый exe базу v4 не открывает.

## Open Questions

Нет. Поставщик TTS, место ключей и пропуск текста при повторе с готовым сценарием зафиксированы выше.
