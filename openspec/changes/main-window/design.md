# Design

## Context

Исходников нет: в репозитории документы и пустой OpenSpec. Требования пустого окна — в `specs/main-window/spec.md`. Мотивация — в proposal.md, раздел Why.

На машине уже стоят Qt 6.10.2 в `C:\Qt1\6.10.2\msvc2022_64` (модули Quick, Qml, QuickControls2) и Visual Studio 2022 Community. Компилятор появляется в окружении только после `vcvars64.bat`. Рядом есть Qt 5.12 в `C:\Qt`; этот набор для каркаса не используется. CMake — 4.3. Проект Printing собирает тот же Qt тем же MSVC через NMake Makefiles.

## Goals / Non-Goals

**Goals:**

- Одно окно Qt Quick, собранное скриптом по образцу входа Printing.
- Токены гайда в одном месте, зоны окна — отдельные элементы с устойчивыми именами.
- Автопроверка пустого состояния без ручного просмотра: высота шапки, цвета, выключенные инструменты, пустые дерево, кадр и таймлайн.

**Non-Goals:**

- Модель папок, SQLite, фильтр поиска, плеер, дорожки таймлайна, FFmpeg, вход Google.
- Установщик NSIS и прочие шаги `build-setup.bat` Printing после сборки.

## Decisions

### Окно на Qt Quick

ТЗ фиксирует Qt 6 и Qt Quick: таймлайн позже станет своим элементом сцены. Каркас сразу сажает зоны в QML, чтобы этап 2 наполнял дерево, а не заменял окно.

Рассматривался Qt Widgets, как в Printing. Для этого продукта он отпадает: принятый стек — Quick, и стол монтажа на виджетах пришлось бы выбрасывать.

`main.cpp` только поднимает движок и грузит модуль. Вся схема окна — QML.

### Сборка как у Printing, без упаковки

`build.bat` повторяет начало `D:\Programm\Printing\build-setup.bat`:

1. `QTDIR=C:\Qt1\6.10.2\msvc2022_64`, если переменная не задана.
2. Вызов `vcvars64.bat` Visual Studio 2022 Community.
3. `cmake -S . -B build -G "NMake Makefiles" -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=%QTDIR%`.
4. Сборка цели приложения и теста, затем тест с `QT_QPA_PLATFORM=offscreen`.

В `CMakeLists.txt`: `cmake_minimum_required(VERSION 3.24)`, `CMAKE_POLICY_VERSION_MINIMUM 3.5` (CMake 4 не принимает слишком старый минимум у зависимостей), C++20, для MSVC `/utf-8`. Компоненты: `Quick`, `Qml`, `QuickControls2`, `QuickTest`.

FetchContent не нужен, обход кириллицы в профиле Git из Printing не переносится.

### Зоны с именами, без данных

Корень `qml/Main.qml`. Рядом тема и пять зон: шапка, левая колонка, кадр, правая колонка, таймлайн, дерево. У каждой зоны `objectName`, чтобы тест находил её без привязки к координатам.

Швы для следующих этапов, без их поведения:

- Дерево — пустой вид, не модель.
- Кадр — пустой прямоугольник 9:16. Свойство режима центра равно `empty`.
- Таймлайн — пустая полоса без клипов.
- Кнопки инструментов — настоящие контролы с `enabled: false`.
- Поиск — поле в шапке. Его текст никуда не привязан, поэтому ввод не создаёт строки дерева и не показывает «Ничего не найдено».
- Кнопка каналов видна, обработчик пустой: нет браузера и нет записи канала.

Знак в шапке — фигура цвета `#ff0033` в зоне 40px. Иконка заголовка Windows — отдельный чёрный знак из файла пользователя: тёмный скруглённый прямоугольник и светлый треугольник. В шапку этот файл не ставится.

### Токены и шрифт

Цвета, высоты и радиусы живут в одном QML-синглтоне темы. Значения берутся из `docs/youtube-dark-style.md`, подстановки «похожими» цветами нет.

Шрифт окна — семейство Roboto, затем Arial. В `assets/fonts/` лежат файлы Roboto весов 400, 500 и 700 (Apache 2.0) и текст лицензии. Они загружаются до показа окна, чтобы на машине без установленного Roboto сценарий шрифта всё равно выполнялся.

### Заголовок, иконка и геометрия

Заголовок окна — строка `YouTube Creator`. Иконка заголовка берётся из `assets/icons/window-icon.png`: это переданный чёрный знак. Файл кладётся в ресурсы и назначается окну до показа. Красный знак шапки остаётся нарисованным в QML и этот файл не использует.

Положение и размер пишутся при закрытии и читаются при запуске. Хранилище — настройки Qt на машине пользователя, без сети и без базы библиотеки. Если сохранённый прямоугольник не пересекает ни один экран, окно открывается в размере по умолчанию в видимой области. Тест подменяет каталог настроек, чтобы не зависеть от уже сохранённого окна разработчика.

### Глифы

Десять инструментов и кнопка каналов рисуются отдельными линейными фигурами одной толщины, со скруглёнными окончаниями, глиф 24px. Цвет выключенного глифа — `text-disabled`. Одинаковый пустой квадрат на всех кнопках не остаётся.

### Проверка через Qt Quick Test

Поведение спеки — свойства окна, не алгоритм. Тест Quick Test грузит окно в `offscreen`, читает `objectName`, высоту шапки, цвета холста и текста, `enabled` инструментов, отсутствие делегатов дерева, клипов и картинки кадра. Ввод в поиск не добавляет строк. Нажатие инструмента и кнопки каналов не меняет пустой кадр и не создаёт канал.

Снимок экрана для приёмки не используется: радиус и цвет проверяются свойствами контролов.

## Risks / Trade-offs

- [Сборка из оболочки без `vcvars64.bat` не видит MSVC] → поддерживаемый вход — `build.bat`, он сам вызывает vcvars.
- [CMake может подхватить Qt 5.12 из `C:\Qt`] → `CMAKE_PREFIX_PATH` жёстко указывает на `C:\Qt1\6.10.2\msvc2022_64`.
- [Offscreen не доказывает пиксель в пиксель совпадение с youtube.com] → тест держит числа гайда в свойствах; визуальный закон остаётся в гайде.
- [Пустые обработчики поиска и каналов легко заполнить логикой этапа 2 или 9 по ходу] → в этом изменении у них нет модели и нет сети. Спека это фиксирует.

## Migration Plan

Пользователей и локальных данных нет. Первая сборка создаёт каталог `build/`. Откат — удалить `build/` и не запускать собранный файл. Отдельного переноса настроек нет.
