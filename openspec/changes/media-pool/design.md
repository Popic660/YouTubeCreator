# Design

## Context

См. proposal.md — Why. Сейчас `CProjectDocument::import_video` вызывает `create_short` и копирует файл в `media/<uuid>/`. Клип уже хранит `asset_id`, но пула нет: ассет живёт только пока на него ссылается ролик. `CDockState` знает две панели (`library`, `timeline`) и три дока. Дерево — `ListView` в `LibraryPane.qml`, глиф папки без язычка. `save` пишет `project.json` напрямую. `library.db` — `user_version` 2, таблицы `folders` и `shorts`.

Требования — в `specs/assets`, `library`, `timeline`, `main-window`. Гайд — `docs/youtube-dark-style.md`. Цвета FilmCraft не брать.

## Goals / Non-Goals

**Goals:**

- Один пул на библиотеку, клип — ссылка.
- Три именованные панели в тех же трёх доках, что уже есть.
- Миграция `user_version` 2 → 3 без потери роликов и копий в `media/`.
- Проверки через методы хранилища и документа, без системного `FileDialog`.

**Non-Goals:**

- Рекурсивное дерево сплитов и плавающие окна.
- Линк файла без копии и диалог relink.
- Отдельный монитор Source на размер кадра 9:16.

## Decisions

### Пул в sqlite, не в json ролика

Таблицы `bins` (id, parent_id, name) и `assets` (id, bin_id, name, kind, relpath, duration_ms, in_ms, out_ms, fingerprint, size). Корень пула — бин с пустым `parent_id`. `PRAGMA user_version = 3`.

Рассматривался каталог на диске как источник правды. Поиск, родитель и метки In/Out тогда разъезжались бы с деревом папок. Sqlite уже держит папки шортсов.

При `open` версии 2: создать таблицы, корневой бин, обойти `shorts/*/project.json`, для каждого `asset_id` вставить строку, если файла ещё нет в `assets`. Ролики не трогать.

### Импорт копирует и ищет отпечаток

`copy_asset` остаётся. Перед копией считаем размер и hash первых и последних 1 МиБ. Совпадение с существующим ассетом — новая строка в том же или другом бине со ссылкой на тот же `relpath`, файл не дублируется.

Рассматривался всегда новый uuid-каталог. Два ролика с одним B-roll тогда ели диск дважды.

Рассматривался линк пути пользователя. ТЗ и текущий дизайн держат копию из-за флешки. Линк — отдельное изменение плюс offline.

Повторный импорт того же файла в тот же бин не плодит вторую карточку: возвращается существующий id.

### Панель медиа — третий `panelId`

`CDockState` получает `mediaDock`, по умолчанию `left`. `libraryDock` остаётся `right`, `timelineDock` — `bottom`. `reset_layout` ставит эту тройку.

Компонент `PanelChrome`: шапка 32px, глиф, заголовок, drag `keys: ["panel"]`. Вкладки дока — чипы гайда вместо голых `Button`. Кадр и `ToolColumn` не становятся панелями.

Рассматривалось дерево сплитов как у FilmCraft (`Node::Split` / `Tabs` / floating). Это новая оболочка поверх рабочего `Main.qml`. Три дока уже стыкуют панели; нехватка была в третьей панели и хроме, не в геометрии.

### In/Out на ассете, insert/overwrite на броске

Метки живут в строке `assets`. Клип при броске копирует их в `in_ms`/`out_ms` и больше от ассета не зависит.

Попадание: зона ±8px от стыка или от края клипа — insert (сдвиг `start_ms` справа). Иначе overwrite на `start` броска: новый клип закрывает интервал, хвост старого режется, соседи не ripple.

Snap: кандидаты — края клипов и `playheadMs`, порог 8px, выключатель на шапке таймлайна. Состояние в `CDockState` или в документе, запомнить между запусками.

«Закрыть разрыв» — команда документа: на выбранной дорожке сдвинуть клипы после дырки влево. Не автоматический ripple при delete: удаление клипа уже есть и оставляет дырку.

### Атомарная запись и журнал рядом с роликом

`save` пишет `project.json.tmp`, `flush`, переименовывает поверх `project.json`.

Журнал: `shorts/<id>/recovery.json` (+ копия клипов) через `QTimer` 1000 мс после последней правки. Нормальный `close` / смена ролика удаляет recovery. При `open_short`, если recovery новее `project.json` и нет флага чистого выхода сессии, UI спрашивает. Тест ставит файл recovery вручную и вызывает `open_short`.

Рассматривался один журнал на всю библиотеку. Правка двух роликов подряд тогда путала бы id.

### Дерево и глифы в нашем наборе

Новые имена в `Glyph.qml`: `folder` с язычком, `chevronRight` / `chevronDown`, `film`, `short`, `audio`, `image`, `bin`, `magnet`. Штрих 2px, round cap, 24px, как Lucide в файле. Не копировать path из FilmCraft `icons.rs`.

Строка: высота 40px, радиус 10px, ховер `tonal`. Сетка медиа: превью 12px, бейдж длительности из гайда. Hover-scrub зовёт уже существующий `CMediaIo::decode_frame` по x/ширина × duration.

## Risks / Trade-offs

- [Старые тесты ждут, что `import_video` возвращает id шортса] → сменить на импорт в пул + явный `create_short` + `place_asset`; фикстуры те же.
- [Два ассета на один relpath, удаление одного] → файл удалять только когда `COUNT(assets.relpath)` и клипы всех `project.json` равны нулю.
- [Overwrite на коротком клипе] → если новый длиннее цели, обрезать новый по дырке, не выталкивать соседей.
- [Hover-scrub тормозит] → кадр кэшировать по (asset_id, квант времени); нет кадра — заглушка, не падение.
- [Журнал каждую секунду на большом json] → снимок только если документ грязный; тот же атомарный путь.

## Migration Plan

1. `open` версии ≤ 2 создаёт `bins`/`assets`, пишет `user_version` 3.
2. Существующие `media/` и `shorts/` остаются. Ассеты регистрируются из клипов.
3. Откат кода: база 3 читается sqlite, неизвестные таблицы старый код не трогает. Откат файла не предусмотрен.
4. Раскладка: отсутствует `mediaDock` в настройках → default left. Старый `library=right`, `timeline=bottom` совместим.

## Open Questions

Нет. Линк без копии и плавающие окна отложены сознательно.
