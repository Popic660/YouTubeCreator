# Design

## Context

Библиотека уже открывает `library.db` (`user_version` 1, таблицы `folders` и `shorts` без пути к файлу). `LibraryPane.selectedId` запоминает строку и никуда её не отдаёт. `FrameView` держит `centerMode: "empty"` и `hasFrameImage: false`. `TimelineHost.clipCount` всегда 0. Десять кнопок — `DisabledTool` с `enabled: false`. Каталогов `media/`, `shorts/`, `exports/` и `cache/` нет. FFmpeg в `CMakeLists.txt` не подключён. Мотивация — в proposal.md, требования — в `specs/`.

Проверки идут через `shell_tests` в offscreen: системный `FileDialog` в тесте не открывают, как уже сделано с папкой библиотеки.

## Goals / Non-Goals

**Goals:**

- Один компоновщик кадра на ползунок: импорт, резка, масштаб и экспорт читают ту же модель клипов.
- Проверки без живого окна: импорт по готовому пути, кадр как картинка, клипы и края в свойствах, экспорт как файл.
- FFmpeg находится рядом с exe так же явно, как `qsqlite.dll`.

**Non-Goals:**

- Второй плеер «файл целиком» рядом с таймлайном.
- Qt Multimedia как источник правды монтажа.
- Сценарий, голос, генерация клипов, OAuth.

## Decisions

### Кадр всегда композит таймлайна

`CProjectDocument` держит клипы открытого ролика. `CFrameCompositor` по времени ползунка собирает картинку 9:16: клип V1 в этом времени, масштаб и положение, поверх — V2 (текст). `FrameView` показывает эту картинку и выставляет `centerMode` в `preview`, `hasFrameImage` в true.

Рассматривался `QMediaPlayer` по пути исходника. Он закрывает этап 3 и ломает этап 4: подрезка и склейка потребовали бы сменить плеер. Один компоновщик с самого импорта: у нового файла один клип на V1 от нуля до длительности.

Пустой черновик документ не открывает: кадр остаётся `empty`. Снятие выбора сбрасывает документ.

### `project.json` — таймлайн, sqlite — карточка

Клипы, входы, выходы, масштаб, положение, громкость и текст живут в `shorts/<id>/project.json`. SQLite на `user_version` 2 добавляет к `shorts` колонки `duration_ms` и `poster_relpath` для дерева. Сценария в схеме нет.

Рассматривалась таблица клипов в sqlite. ТЗ уже отводит таймлайн файлу проекта; дерево не должно читать json на каждую строку.

Миграция при `open`: если `user_version` 1, `ALTER TABLE` двух колонок и `PRAGMA user_version = 2`. Второй файл базы не создаётся.

### Копия в `media/`, не алиас пути пользователя

Импорт копирует файл в `media/<asset_id>/` и пишет `asset_id` в клип. Каталоги `media/`, `shorts/<id>/`, `exports/` и `cache/waveforms/` создаются при первом нужном действии, не при выборе папки библиотеки.

Рассматривалась ссылка на исходный путь. Файл на флешке или переименование вне программы оставило бы дыру в ролике.

Имя нового ролика — имя файла без расширения. Импорт в существующий черновик не меняет имя.

Удаление ролика после подтверждения снимает строку, каталог `shorts/<id>/` и ассет, на который больше нет ссылок. `CLibraryStore::delete_short` остаётся точкой удаления, файлы — шаг той же операции.

### FFmpeg в процессе, не `ffmpeg.exe` как монтажный стол

Декод кадра по времени, пики волны и кодирование экспорта идут через библиотеки `avformat`, `avcodec`, `avutil`, `swscale`, `swresample`. CMake получает `FFMPEG_ROOT` так же, как Qt: переменная среды или кэш. После сборки нужные DLL копируются рядом с `youtube-creator.exe` и `shell_tests.exe`.

Рассматривался вызов `ffmpeg.exe` с `filter_complex`. Скраб ползунка и покадровый тест в offscreen с ним неудобны, а живой кадр легко разъехался бы с экспортом.

Рассматривался только `Qt6::Multimedia`. В Qt 6.10 FFmpeg уже есть как бэкенд плеера, но склейка, кроп и текст — всё равно наш композит. Зависимость от Multimedia для этой задачи не нужна.

`build.bat` без `FFMPEG_ROOT` завершается с той же формой ошибки, что без Qt.

Экспорт пишет `exports/<id>.mp4`, 1080×1920, yuv420p, H.264, AAC. Композит для файла тот же, что для `FrameView`, масштаб линейный до 1080×1920.

### Вписывание в 9:16 — cover

Первый клип масштабируется так, чтобы заполнить 9:16, лишнее обрезается. Горизонтальный исходник даёт вертикальное окно без полей. Кнопки масштаба и положения правят уже этот transform. Значения в json: `scale` (1.0 после cover) и смещение относительно центра кадра.

Рассматривался contain (весь кадр исходника плюс поля). ТЗ хочет заполненный вертикальный кадр шортса.

### Текст — клип V2 без файла

Клип типа `text` хранит строку, кегль и цвет. Композитор рисует его поверх V1. Отдельный png на диск не пишется. Анимация и маски не входят.

### Отмена и автосохранение

Стек команд на `CProjectDocument`. Каждое изменение клипов пушит снимок, который можно снять и вернуть. После успешной команды документ пишет json. Отдельной кнопки «Сохранить» нет. Тест не ждёт таймер: вызывает ту же запись, что и команда.

### Волны в кэше

Пики считаются при импорте аудио или видео со звуком и пишутся в `cache/waveforms/<asset_id>`. Таймлайн рисует кэш, а не декодирует файл на каждый кадр списка. Нет кэша — полоса без волны, не падение.

### Проверки

Новые случаи — `tests/tst_timeline.qml` в том же `shell_tests`. Короткий вертикальный и короткий горизонтальный ролик лежат в `tests/fixtures/`. Импорт идёт методом хранилища по пути фикстуры. Offscreen не слушает звук: громкость проверяется значением клипа и тем, что экспортёр получает тот же коэффициент.

Тест пустого черновика по-прежнему ждёт `centerMode` `empty`, `hasFrameImage` false, `clipCount` 0 и выключенные кнопки. Тест `test_toolsStayDisabled` остаётся верным для окна без выбранного ролика с клипами.

`hasFrameImage` после импорта и выбора — true, `clipCount` ≥ 1. После снятия выбора снова empty.

## Risks / Trade-offs

- [На машине нет FFmpeg, сборка падает] → `build.bat` требует `FFMPEG_ROOT` и печатает путь-пример; без него шаг [1/3] выходит с ошибкой, а не собирает плеер-заглушку.
- [Offscreen не доказывает пиксель в пиксель совпадение экспорта с экраном] → тест сравнивает геометрию файла 1080×1920, число склеек через края клипов в json и то, что экспортёр читает тот же документ, что кадр.
- [Системный диалог файла не открыть в offscreen] → спека импорта покрыта вызовом по готовому пути; в панели проверяется, что действие импорта есть.
- [Требование `main-window` про выключенные инструменты] → для окна без ролика с клипами оно остаётся верным. Включение кнопок покрывает `frame-tools`.
- [Долгий декод на скрабе] → кадр по времени запрашивается у декодера с seek; волна не пересчитывается на скрабе.
- [Старая библиотека `user_version` 1] → `open` мигрирует схему; ролики без файла остаются черновиками, каталоги медиа ещё не нужны.

## Migration Plan

Существующие `library.db` с версией 1 открываются и получают две колонки. Откат изменения кода: база версии 2 остаётся читаемой как sqlite, лишние колонки новому старому коду версии 1 неизвестны — откат кода без отката файла не предусмотрен. Пользователь может выбрать другую папку. Геометрия окна и доки не трогаются.
