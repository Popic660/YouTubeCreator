# Design

## Context

См. proposal.md — Why. Требования — в `specs/pipeline`, `library`, `assets`, `timeline`.

Сейчас `library.db` — `user_version` 4, у ролика есть `topic`, `script`, статус `draft` / `generating`. `CPipeline` после голоса вызывает `import_media` и `place_asset` на `a1` и ставит снова `draft`. `CHttpTransport` умеет только синхронный POST. `CSecretStore` хранит один OpenAI-совместимый ключ. `place_asset` для видео на `v1` при наличии звука в файле копирует его на `a1` и каждый раз переписывает постер. Шаблон чата просит свободный текст; сцены не разбираются.

## Goals / Non-Goals

**Goals:**

- Тот же контракт инструмента: вход, выход, отмена, прогресс, ошибка. Конвейер этапа 8 — текст, голос, видео по сценам, постер с кадра, 16:9 обложка.
- Kling за заглушкой транспорта, тесты без живой сети.
- Видео сцены проходит тот же ingest, что ручной файл, но не затирает голос на `a1`.

**Non-Goals:**

- Второй адаптер (Veo, LTX, локальный Wan).
- Callback-URL с публичного сервера.
- JWT Access Key / Secret Key старого Kling API.
- Нарезка TTS по сценам.

## Decisions

### Оркестратор продолжает голос, не отдельный конвейер

`CPipeline` после успешного `run_voice_step` вызывает `run_video_step`, затем пишет постер с кадра 0 и `run_cover_step`. `finish_ok` ставит статус `ready`. Шаги `video` и `cover` пишутся в `tasks.step`.

Рассматривался отдельный `CVideoPipeline`. Прогресс, отмена и повтор тогда разъехались бы с карточкой этапа 7.

Повтор: если сценарий есть — пропуск текста; если на `a1` уже есть клип — пропуск голоса; если число клипов на `v1` меньше числа сцен — генерация только оставшихся сцен с `start_ms` после хвоста V1; если клипы и постер есть, а обложки нет — только cover.

Без ключа Kling после голоса: `needsSettingsMessage`, статус `draft`, сценарий и голос на месте. Чат-ключ по-прежнему нужен, чтобы стартовать текст.

### Разбор сцен из JSON в сценарии, иначе один клип

`CChatTool` просит JSON вида `{"scenes":[{"prompt":"...","duration_s":5}]}` плюс стиль папки. В `script` пишется сырой ответ. `parse_scenes` берёт первый JSON-объект со массивом `scenes`. Пустой или битый JSON — одна сцена: весь текст, `duration_s` 5. Длительность клипа режется в `[3, 20]` (лимит Kling 4.0 Flash).

Рассматривалось хранить сцены отдельной колонкой. Поиск и карточка уже читают sqlite; сырой сценарий достаточен, разбор дешёвый.

### Kling 4.0 Flash через POST + опрос GET, не callback

База по умолчанию `https://api-singapore.klingai.com`. Новый API Key: `Authorization: Bearer`. Умолчание модели — `kling-4.0-flash`. Пользователь меняет адрес, имя модели и ключ в том же диалоге настроек отдельными полями.

На сцену:

1. `POST /text-to-video/kling-4.0-flash` с `settings.aspect_ratio = 9:16`, `resolution = 720p`, `duration`, `options.watermark_info.enabled = false`.
2. Опрос `GET /tasks?task_ids=<id>` до `succeeded` / `failed` / отмены. Пауза 2 с, потолок 10 мин на сцену. Callback не используется: у локального окна нет входящего URL.
3. Скачать `outputs[].url` типа `video` (GET, без ключа, если CDN). Файл во временный путь, затем `import_media` и `place_asset` на `v1` с `copy_audio = false`.

У Flash T2V нет флага «без звука». Если в mp4 дорожка есть, на `a1` её всё равно не копируем.

`CHttpTransport` получает `get(url, bearer)`. Заглушка берёт ответы из той же очереди, что `post`. Тест кладёт JSON создания, JSON `succeeded` с `url` и байты фикстуры. Живой Kling из `shell_tests` не вызывается.

Рассматривался Vertex/Veo. 8 с на клип, звук в тарифе, другой SDK. Рассматривался JWT AK/SK — это legacy path.

### `place_asset` не копирует звук конвейерного видео

Новый аргумент `copy_audio` (по умолчанию true для перетаскивания из медиа). Конвейер передаёт false. Иначе текущая ветка «видео на v1 с audio → клип на a1» затрёт TTS.

Постер карточки после всех сцен: `write_poster` по файлу первого клипа V1 в нуле, один раз. Промежуточные `place_asset` конвейера постер не переписывают (иначе победит последняя сцена).

### Обложка — Kling Image, файл ролика, не YouTube

`CCoverTool`: async image API того же ключа Kling (Image 3.0, 16:9). Результат — `shorts/<id>/youtube_cover.jpg`. Если сторона не 1280×720, масштабировать с обрезкой по центру. Колонка `shorts.cover_relpath`. Загрузки на канал нет.

Рассматривался кадр 9:16, растянутый в 16:9. По бокам поля, в поиске YouTube выглядит хуже отдельной горизонтальной картинки.

Ошибка обложки не откатывает клипы и постер.

### Ключ Kling в том же DPAPI JSON

`CSecretStore` добавляет `kling_base_url`, `kling_model`, `kling_image_model`, `kling_api_key`. Поле ключа после `save` пустое, `hasKlingKey` отдельно от `hasKey`. Тест — память; в `library.db` и `project.json` строки ключа нет.

Рассматривался тот же `api_key`, что у чата. Kling — другой кабинет и Bearer.

### Схема `4 → 5`

`ALTER TABLE shorts ADD COLUMN cover_relpath TEXT NOT NULL DEFAULT ''`. `PRAGMA user_version = 5`. Тема, сценарий, задачи, ассеты не трогать. Откат схемы нет: старый exe базу v5 не открывает, как у 3 → 4.

`interrupt_running_tasks` по-прежнему переводит `running` в `interrupted` и `generating` в `draft`.

## Risks / Trade-offs

- [Flash всё же пишет звук в mp4] → `copy_audio = false`, голос на `a1` не затирается.
- [Сценарий без JSON] → один клип на весь текст, длительность 5 с (кламп 3–20).
- [Опрос 10 мин] → отмена рвёт текущий GET; повтор продолжает с числа клипов на V1.
- [CDN URL протухает за 30 дней] → сразу копируем в `media/`, как ingest.
- [Повтор видео после двух успешных сцен] → не перегенерируем уже лежащие клипы V1, только хвост.

## Migration Plan

При `open` версии 4: колонка `cover_relpath`, `user_version = 5`. Ролики без обложки — пустая строка, статус как был. Ключ Kling пользователь вводит сам.

## Open Questions

Нет. Поставщик Flash, постер с кадра 0, 16:9 обложка в файле ролика и пропуск готовых шагов при повторе зафиксированы выше.
