# Design

## Context

Пустое окно уже собрано: `LibraryPane` — полоса шириной 240px со свойством `rowCount`, поиск шапки никуда не пишет, настройки окна лежат в `QSettings` организации `YouTubeCreator` и приложения `MainWindow`. Тест оболочки перед запуском подменяет каталог этих настроек на временный. В установленном Qt 6.10.2 есть модуль `Qt6::Sql` и драйвер `QSQLITE`. Мотивация — в proposal.md, раздел Why. Требования — в `specs/library/spec.md`.

## Goals / Non-Goals

**Goals:**

- Одно хранилище на выбранную папку и одна модель строк для дерева.
- Проверки библиотеки в том же `shell_tests`, без ручного диалога выбора папки и без библиотеки разработчика.
- Драйвер SQLite находится рядом с собранным exe.

**Non-Goals:**

- Полнотекстовый индекс, `project.json`, каталоги медиа и отдельные таблицы каналов.
- Второй плеер, импорт файла и включение инструментов кадра.

## Decisions

### Хранилище и модель — разные объекты

`CLibraryStore` владеет файлом `library.db` и запросами. `CLibraryModel` — плоский список видимых строк для панели: папка или ролик, глубина, раскрытие. Панель рисует строки, SQL в QML не попадает.

Объект создаёт окно и каждый тест заново. Синглтоном хранилище не делается: тесты открывают разные временные папки в одном процессе, и общий синглтон оставил бы чужие данные следующему окну.

Рассматривался `QSortFilterProxyModel` поверх дерева Qt. Он плохо показывает предка совпадения, если сам предок по имени не совпал. Плоский список собирает таких предков явно и даёт тестам один `rowCount`.

### Схема `library.db`

Версия схемы — `user_version` 1.

```
folders(id, parent_id, name, prompt)
shorts(id, folder_id, name, status)
```

`id` — текст `QUuid` без фигурных скобок. `parent_id` корня пустой. `prompt` — только собственный текст папки. `status` нового ролика всегда `draft`; другого значения этот этап не пишет. Индексы на `folders.name`, `shorts.name` и `shorts.folder_id`.

Колонок сценария, постера и таймлайна нет. Следующий этап добавит их миграцией `user_version`, а не вторым файлом.

Отдельная таблица FTS не нужна: библиотека локальная, отбор по подстроке имени делает модель через `QString::contains` без учёта регистра. Индекс имён остаётся в SQLite, как в ТЗ, и служит чтению, а не морфологии.

Соседи в одной папке упорядочены по имени без учёта регистра, при равном имени — по `id`.

### Эффективный промпт

Считается при чтении, от корня к папке. Пустые собственные тексты пропускаются. Непустые склеиваются через пустую строку, родительский текст раньше своего. Смена промпта родителя не переписывает строку ребёнка.

### Путь библиотеки

Ключ `library/path` в тех же `QSettings`, что и геометрия окна. Нет ключа или каталог недоступен — библиотека закрыта, панель предлагает выбрать папку. Выбор в окне — `FolderDialog`. Тест этот системный диалог не открывает: он вызывает открытие хранилища по уже созданному временному каталогу.

Поиск применяется только к открытой библиотеке. Пока папка не выбрана, ввод не заменяет приглашение выбрать папку текстом «Ничего не найдено». Так остаётся верным существующий тест пустого поиска.

### Меню, диалоги, перетаскивание

Меню папки — всплывающая панель фона `#282828`. Переименование, промпт и подтверждение удаления — диалоги того же фона. Поле ввода с радиусом 4px. Подтверждение удаления — залитая кнопка, отмена — тональная. В диалоге промпта собственный текст редактируется, унаследованный показан только для чтения.

Строка папки принимает сброс. Сброс ролика вызывает перенос в эту папку, сброс папки — смену родителя. Перенос в себя или в своего потомка хранилище отклоняет. Тест вызывает тот же обработчик сброса, что и зона сброса, и не тащит мышь по offscreen-окну.

Удаление поддерева идёт одной транзакцией. Нужно ли подтверждение, модель спрашивает у хранилища: в поддереве есть ролик или нет.

### Смена папки

Кнопка смены папки видна и при открытой библиотеке. Она снова открывает `FolderDialog`. После согласия хранилище закрывает текущую базу, открывает выбранный каталог и вызывает `remember`. Отказ диалога базу не трогает. Прежняя `library.db` на диске остаётся: меняется только открытый путь.

### Значок поиска и вид дерева

Кнопка поиска в шапке получает тот же линейный глиф, что и инструменты: лупа, цвет `#f1f1f1`. Пустая заливка кнопки без глифа не остаётся.

Строка папки рисует глиф папки той же толщины. Глубина строки сдвигает её вправо на шаг 12px. На каждом шаге до родителя стоит вертикальная линия цвета `outline`. Ролик остаётся заглушкой без глифа папки.

### Диалоги по центру окна

Диалоги имени, промпта и удаления не якорятся к панели шириной 240px. После открытия их кладут в центр оверлея главного окна: левый край `(ширина окна − ширина диалога) / 2`, верхний край так же по высоте. Если диалог выше окна, его верх совпадает с верхом окна, а не уходит за край. Тест читает положение диалога относительно `mainWindow` и проверяет, что прямоугольник диалога лежит внутри окна.

### Размер и перенос панелей

Середина — одна группа, её не разрывают: кадр 9:16 и кнопки работы по его сторонам. Эта группа остаётся в центре, как холст в студии на снимках.

Вокруг неё три дока: левый, правый и нижний. Сейчас переносятся две панели — дерево папок и таймлайн. У панели есть шапка, за которую её тащат. Пока её держат над доком, док подсвечивается: это место, куда она встанет. Сброс ставит панель в этот док. Если там уже есть панель, обе становятся вкладками, видна одна. Пустой док места не занимает.

По умолчанию дерево в правом доке шириной 240px, таймлайн в нижнем. Кнопки слева и справа от кадра. Это схема ТЗ, пока пользователь ничего не двигал.

Разделитель есть у каждого занятого дока. Боковые меняют ширину, нижний — высоту. Ширина дока с деревом не опускается так, чтобы имя папки перестало читаться. Кадр после тяги остаётся видимым.

Размеры и положение пишутся в `QSettings` рядом с `library/path` и читаются при следующем запуске: `layout/libraryDock`, `layout/timelineDock`, `layout/leftWidth`, `layout/rightWidth`, `layout/bottomHeight`. Значения дока — `left`, `right` или `bottom`. Тест вызывает тот же обработчик сброса, что и подсвеченная зона, и не проверяет системный жест мыши.

Плавающие окна и док внутри дока на этих снимках не требуются: панели живут в трёх доках вокруг кадра. Новые деревья следующих этапов садятся в те же доки, но этот этап их не заводит.

### Сборка драйвера

`find_package` добавляет компонент `Sql`. После сборки `qsqlite.dll` копируется в `sqldrivers` рядом с `youtube-creator.exe` и `shell_tests.exe`. Каталог `build/` у NMake один, копии достаточно для обоих файлов. `windeployqt` по-прежнему не вызывается.

### Проверки

Новые случаи ложатся в `tests/tst_library.qml` и выполняются существующей целью `shell_tests`. У каждого случая свой временный каталог. Тест, который открывает `Main`, в начале и в конце очищает `library/path`, чтобы пустое окно следующего случая не увидело чужую библиотеку.

`LibraryPane.rowCount` считает видимые строки дерева. Приглашение выбрать папку и текст «Ничего не найдено» строками не являются. У текста пустого поиска остаётся `objectName` `notFoundMessage`.

## Risks / Trade-offs

- [Рядом с exe нет `sqldrivers/qsqlite.dll`, и база не открывается] → копирование плагина шагом сборки, тест падает на открытии временной базы, а не молча показывает пустое дерево.
- [Тест библиотеки оставляет путь в общих настройках процесса] → путь очищается до и после случая, каталог настроек оболочки по-прежнему временный.
- [Системный диалог папки не проверить в offscreen] → спека выбора покрыта вызовом открытия по готовому пути; в панели проверяется, что кнопка выбора есть, пока библиотека закрыта.
- [Требование изменения `main-window` всё ещё говорит, что ввод в поиск не заполняет дерево] → для закрытой библиотеки это остаётся верным. Для открытой библиотеки действует спека `library`. При архивации `main-window` это требование нельзя переносить как поведение открытой библиотеки.
- [Перенос панелей расходится с жёсткой схемой каркаса] → пока раскладку не меняли, дерево справа, таймлайн снизу, кнопки у кадра, как в ТЗ. Сохранённые доки читаются после геометрии окна.

## Migration Plan

Пользовательских библиотек ещё нет. Первое открытие папки создаёт `library.db`. Откат — удалить этот файл и ключ `library/path`. Геометрия окна живёт в других ключах и не трогается.
